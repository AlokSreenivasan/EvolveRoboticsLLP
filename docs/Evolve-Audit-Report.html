1. Architecture snapshot

Layered presentation → services → domain with React Context auth (no Redux/Zustand). Custom home tab bar; Admin nested stack gated client-side. Content lives in Firestore subscriptions via HomeFeedContext (~8 live listeners when Main is active).

Strengths: typed domain models, signup Auth rollback, account deletion, allowBackup=false, admin content writes mostly rule-gated, structured appAlert UX.

Gaps: security rules holes, almost no tests, no Error Boundaries / Crashlytics, docs still RN template.

8. Platform & store readiness

Package com.evolve · minSdk 24 · targetSdk 35 · versionCode 1 — SDK targets are fine. Blockers: debug signing on release, committed secrets, admin privilege escalation, quiz integrity, Privacy/Terms links for Data Safety / policy, brand assets. iOS (App Store) — Blocked

Bundle ID still org.reactjs.native.example.Evolve. Empty App Icons. Push incomplete. Empty location string. Incomplete Privacy Manifest data types. Signing team / entitlements not production-ready. Plus shared blockers: Firestore role create, secrets, legal links, kids/age compliance if under-13 content applies.

Policy compliance notes

  • Account deletion exists (PrivacySettingsScreen + deleteAccountService) — required for both stores.
  • Privacy Policy / Terms UI present but not wired — likely rejection / Data Safety failure.
  • Kids track + PII without age gate risks COPPA / App Store kids category scrutiny.
  • Declare collecting data accurately in Play Data Safety and PrivacyInfo.xcprivacy before submit.

9. Prioritized production roadmap

  • P0 — Security rules: Lock Firestore create role to user; audit existing admins; tighten isPublished + answer-key reads; admin-only Storage CMS writes.
  • P0 — Secrets: Rotate YouTube key; gitignore .env; move key server-side; scrub history if repo shared.
  • P0 — Quiz integrity: Server-side exam/quiz scoring (callable); stop trusting client correctCount/xpEarned.
  • P0 — Packaging: Android release signing; iOS production Bundle ID + Firebase/Google Sign-In rebuild; App Icons; remove empty location key.
  • P0 — Legal / compliance: Wire Privacy Policy & Terms URLs; complete PrivacyInfo + Play Data Safety; age gate if kids track includes under-13.
  • P1 — Resilience: Fix Google profile provisioning + stale role hydration; Error Boundary + Crashlytics; iOS Push entitlements/APNs.
  • P1 — Release polish: Enable R8; brand Android adaptive icons/splash; align version numbers; CI lint/test/rules.
  • P2 — Quality: Expand tests (auth, guards, scoring); HomeFeed listener optimization; accessibility; App Check; product docs.
Scores rationale. Health 6.0 reflects architecture maturity and feature depth. Production readiness 3.5 reflects ship-blocker density. Fixing the P0 security and packaging items would likely raise production readiness into the 7–8 range before soft launch.
